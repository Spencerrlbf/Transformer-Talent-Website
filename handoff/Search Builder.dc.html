For implementation — where each state comes from

The switcher above is review scaffolding only — do not build it. Each state is a response from POST /api/dashboard/sourcing/preview with { jobId, query }, held in one preview state variable. Any edit to any field resets it to idle, so a run can never start against a stale count.

StateAPI responseWhat renders
Building no request yet, or any field edited Form only. No banner, no way to start a run.
Checking… request in flight Preview button reads “Checking…” and is disabled.
Ready to import ok: true Green banner when creditsAvailable ≥ total. “Import all N” POSTs to /sourcing/runs with matchEstimate, then routes to the run view.
Not enough credits ok: true Same response, creditsAvailable < total. Also reached when /sourcing/runs returns 402 — take available from that body. No start button.
Too broad code: "too_broad" Hard stop above maxImport. Amber banner; no start button. The three narrowing chips are new — each applies its filter and re-previews.
No matches code: "no_matches" Neutral banner, loosen-the-filters copy.
Error non-2xx, or network failure Same neutral banner shell: “Something went wrong / The preview couldn’t run. Try again in a moment.”

Query shape, the label map and the one-line run summary are already in sourcing/types.ts (QueryDraft, queryFromDraft, draftFromParams, summarizeParams) — reuse them rather than re-deriving. The company typeahead is GET /sourcing/companies?q=, debounced 300ms at 2+ characters, storing the LinkedIn URL as the value and the display name in companyLabels.

The preview is the guardrail: no run can start until a count comes back, and any edit invalidates the count. Too broad is a hard stop above the import ceiling; not enough credits is a soft stop with a top-up path. The three suggestion chips on the too-broad state are new — they apply the filter that would bring the count down.
